# 本地测试实验流程（无设备 Mock 模式）

在本地没有 PLC、配料机、炉子、离心机、XRD 等设备时，可通过 **Mock 模式** 完整跑通 `experiment_api` 的整条流程，用于联调、演示或自动化测试。

## 1. 开启 Mock 模式

**方式一：环境变量（推荐）**

```bash
# Windows PowerShell
$env:MOCK_DEVICES="true"
$env:MOCK_STEP_DELAY="1"
python -m uvicorn app:app --host 0.0.0.0 --port 8113

# Windows CMD
set MOCK_DEVICES=true
set MOCK_STEP_DELAY=1
python -m uvicorn app:app --host 0.0.0.0 --port 8113

# Linux / macOS
export MOCK_DEVICES=true
export MOCK_STEP_DELAY=1
python -m uvicorn app:app --host 0.0.0.0 --port 8113
```

**方式二：.env 文件**

在项目根目录 `.env` 中增加：

```ini
MOCK_DEVICES=true
MOCK_STEP_DELAY=1.0
```

然后正常启动：

```bash
python -m uvicorn app:app --host 0.0.0.0 --port 8113
```

- `MOCK_DEVICES=true`：启动时**不连接真实设备**，实验编排器内配料/热处理/XRD 三步**只做短时等待后返回成功**。
- `MOCK_STEP_DELAY`：每步模拟耗时（秒），默认 1，便于观察阶段切换。

## 2. 完整流程测试步骤

流程会依次经过：**配料** → **等待熔封确认** → **等待加热炉上料确认** → **热处理** → **等待 XRD 上样确认** → **XRD 测试** → **完成**。  
在“等待 xxx 确认”阶段需要调用对应 confirm 接口，流程才会继续。

### 2.1 启动实验（LLM 规范 JSON 入参）

```bash
curl -X POST "http://127.0.0.1:8113/api/experiment/flux" \
  -H "Content-Type: application/json" \
  -d @../data/llm_output.json
```

或使用内联 JSON（与 `data/llm_output.json` 结构一致）：

```bash
curl -X POST "http://127.0.0.1:8113/api/experiment/flux" \
  -H "Content-Type: application/json" \
  -d "{\"配方ID\":\"rec_0002\",\"实验目的\":\"高温热电材料研究\",\"工艺配方\":{\"原料\":\"Y, Er, Mn, Si\",\"原料摩尔比_标准化\":\"RE:Mn:Si = 0.5-1.5:1:1\",\"配料总总量\":5},\"温度程序\":{\"升温到最高温时间_h\":4.42,\"最高温段保温温度_摄氏\":1350,\"最高温段保温时间_h\":5,\"降温速率_主降温_℃每小时\":50,\"降温时间_主降温_h\":11}}"
```

返回示例：`{"status":"started","message":"...","experiment_id":"...","phase":"mixing",...}`

### 2.2 轮询状态

```bash
curl -s "http://127.0.0.1:8113/api/experiment/status"
```

Mock 下约 1 秒后 `phase` 会变为 `waiting_seal_confirm`，`is_paused` 为 `true`。

### 2.3 熔封确认

```bash
curl -X POST "http://127.0.0.1:8113/api/experiment/flux/confirm_seal"
```

### 2.4 再次查状态

此时应为 `waiting_thermal_load`，等待“加热炉上料”确认。

### 2.5 加热炉上料确认（可选传炉号/曲线名）

```bash
curl -X POST "http://127.0.0.1:8113/api/experiment/flux/confirm_thermal_load" \
  -H "Content-Type: application/json" \
  -d "{\"oven_id\":1,\"qty\":1}"
```

### 2.6 轮询状态

约 1 秒后为 `waiting_xrd_ready`。

### 2.7 XRD 上样确认

```bash
curl -X POST "http://127.0.0.1:8113/api/experiment/flux/confirm_xrd_ready"
```

### 2.8 最后轮询状态

约 1 秒后应为 `phase: "completed"`，整条实验流程在 Mock 下跑完。

## 3. 一键脚本示例（PowerShell）

可将上述步骤写成一个脚本，便于反复测试（需先开启 Mock 并启动服务）：

```powershell
# 假设服务已启动且 MOCK_DEVICES=true
$base = "http://127.0.0.1:8113"
$body = Get-Content -Raw (Join-Path $PSScriptRoot "..\data\llm_output.json")

Invoke-RestMethod -Method Post -Uri "$base/api/experiment/flux" -Body $body -ContentType "application/json"
Start-Sleep -Seconds 2
Invoke-RestMethod -Method Get -Uri "$base/api/experiment/status"
Invoke-RestMethod -Method Post -Uri "$base/api/experiment/flux/confirm_seal"
Invoke-RestMethod -Method Post -Uri "$base/api/experiment/flux/confirm_thermal_load" -Body '{"oven_id":1,"qty":1}' -ContentType "application/json"
Start-Sleep -Seconds 2
Invoke-RestMethod -Method Post -Uri "$base/api/experiment/flux/confirm_xrd_ready"
Start-Sleep -Seconds 2
Invoke-RestMethod -Method Get -Uri "$base/api/experiment/status"
```

## 4. 小结

| 项目       | 说明 |
|------------|------|
| 开启方式   | 环境变量或 .env：`MOCK_DEVICES=true` |
| 行为       | 不连接设备；配料/热处理/XRD 各步仅等待 `MOCK_STEP_DELAY` 秒后返回成功 |
| 测试目标   | 状态机阶段切换、confirm 接口顺序、GET /status 返回与 phase 一致 |
| 生产环境   | 务必不要设置 `MOCK_DEVICES=true`，否则不会连真实设备 |
